# PUBLICATION RULES

This document is the internal source of truth for the public portfolio.

Public portfolio must:
- Showcase projects that are genuinely built or documented.
- Label project status honestly.
- Describe capabilities at a useful architectural level.
- Avoid exposing proprietary implementation details.

NEVER publish:
- API keys
- passwords
- credentials
- .env contents
- database credentials or connection strings
- private client information
- proprietary prompts
- detailed internal decision logic
- security mechanisms
- unpublished business strategies
- private datasets
- sensitive infrastructure details

Allowed public status labels:
- Built / Working
- Active Development
- Prototype
- Concept / R&D
